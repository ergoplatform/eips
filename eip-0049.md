# Prepaid Storage Rent with Archival and Revival

- Author: TheTrunk
- Status: Proposed
- Created: 22-September-2026
- Last edited: 22-September-2026
- License: CC0
- Forking: Hard Fork

## Abstract

This proposal replaces the current storage-rent enforcement mechanism with a prepaid,
continuous-depletion model. Instead of a binary event every 1,051,200 blocks where
underfunded boxes are claimable in their entirety by third parties, boxes deplete their
rent budget continuously per block. When exhausted, boxes enter an archived state
(pruned from the active UTXO set) that the owner can revive at any time by paying
accrued rent. Third parties cannot claim another user's assets under any circumstance.

## Motivation

The current storage-rent mechanism serves a legitimate purpose: funding state storage
and providing post-emission miner income. However, the enforcement branch — whole-box
confiscation when rent cannot be paid — creates a systemic risk for token custody.

On-chain observation (September 2026) shows that automated rent-collection operations
actively monitor for boxes reaching eligibility and claim them within minutes:

- Approximately 1,400–1,850 boxes per day are claimed chain-wide
- Boxes holding tokens (including stablecoins, wrapped assets, and NFTs) are
  confiscated in their entirety when underfunded
- The median time between a box becoming claimable and being claimed is
  approximately 6 minutes
- Professional collection operations have processed over 77,000 transactions each

The core issue is that the confiscation branch applies to all contents of an
underfunded box, not just the ERG needed to cover the storage cost. A box holding
tokens worth significantly more than the rent due is still confiscated entirely if
its ERG balance is below the rent threshold.

This creates a practical barrier to token issuance and long-term storage of value
on Ergo: any token held in a box that falls below ~0.15 ERG is on a timer to
confiscation, regardless of the token's value.

### Design Goals

1. Preserve rent as a storage cost mechanism
2. Preserve state cleanup incentive
3. Eliminate third-party asset confiscation
4. Eliminate the "cliff" (binary eligibility event)
5. Maintain backward compatibility where feasible

### Prior Art

| Chain | Approach | Third-party confiscation? |
|---|---|---|
| Solana | Rent-exempt minimums (mandatory at creation) | No |
| Cardano | Min-ADA per UTxO (mandatory at creation) | No |
| Nervos | State storage priced in the native asset | No |
| Ethereum | Gas on writes; statelessness roadmap | No |

## Specification

### Overview

Three coordinated changes:

1. Continuous rent depletion — rent deducted per block, not per 4-year period
2. Archival instead of confiscation — exhausted boxes are archived, not claimable
3. Revival mechanism — owners can revive archived boxes at any time

### Continuous Rent Depletion

Replace periodic rent with per-block depletion:

```
RENT_PER_BLOCK = RENT_FEE_PER_PERIOD / STORAGE_PERIOD
              ≈ 0.0000000951 ERG
```

The rent owed on any box at height H is:

```
rent_owed(H) = (H - box.creationHeight) × RENT_PER_BLOCK
rent_remaining(H) = max(0, box.value - rent_owed(H) - MIN_BOX_VALUE)
```

Properties:
- A box with 1 ERG covers approximately 40 years
- Rent status is deterministically computable from creation height and value
- No separate tracking or transaction is needed
- No collector or third party is involved

### Archival State

A box is archived when `box.value - rent_owed(currentHeight) < MIN_BOX_VALUE`.

Archived boxes:
- Are removed from the active UTXO set (state cleanup achieved)
- Still exist in the blockchain's immutable history
- Retain their original script (propositionBytes)
- Retain all tokens
- Cannot be claimed or collected by any third party

Archival is a state of temporary inaccessibility, not a transfer of ownership.
The box's contents remain under the control of the original script.

### Revival Mechanism

An owner revives an archived box by submitting a revival transaction:

```
revival_tx = {
    inputs: [
        {
            boxId: <archived_box_id>,
            spendingProof: <owner_signature>,
            extension: {
                proof: <merkle_proof_of_existence>,
                block_height: <original_creation_block>,
                tx_index: <index_in_block>,
                output_index: <output_index>
            }
        },
        <funding_box>
    ],
    outputs: [
        {
            ergoTree: <same_as_archived_box>,
            value: <new_erg - overdue_rent - fee>,
            tokens: <all_tokens_from_archived_box>,
            creationHeight: <current_height>
        }
    ]
}
```

Overdue rent is capped:

```
overdue_rent = min(
    (current_height - last_funded_height) × RENT_PER_BLOCK,
    MAX_RENT_CAP
)
```

### Minimum Box Value

Every output box must have value >= RENT_EXEMPT_MINIMUM:

```
RENT_EXEMPT_MINIMUM = RENT_PER_BLOCK × BLOCKS_PER_40_YEARS
                    ≈ 1.0 ERG
```

Existing boxes below this threshold are grandfathered (they follow archival rules).

## Implementation Notes

### Node changes

1. UTXO set pruning: Periodically remove archived boxes from the active UTXO set.
2. Revival validation: Verify Merkle proof, check script, prevent double-revival.
3. Rent calculation: Computed from (currentHeight - creationHeight) × RENT_PER_BLOCK.

### Wallet changes

1. Box building: Attach >= RENT_EXEMPT_MINIMUM ERG to every output.
2. User indication: Show remaining rent coverage per box.
3. Revival UI: A "revive archived boxes" feature.

### Activation Schedule

1. Phase 1 (height H1): Confiscation branch disabled.
2. Phase 2 (height H2, H1 + ~6 months): Minimum box value enforcement.
3. Phase 3 (ongoing): Archival and revival mechanisms activate.

## Rationale

### Why continuous depletion rather than periodic?

The 4-year periodic model creates a cliff: a binary moment when a box either pays
or is confiscated. A continuous model has no cliff — rent is a slow, predictable
cost with no moment of crisis.

### Why archival rather than permanent deletion?

State cleanup is a legitimate motivation. However, cleanup should not transfer
ownership of assets. Archival achieves state cleanup while preserving property rights.

### Why a minimum box value?

Prevents the creation of boxes that will be archived quickly. Every new box has
decades of coverage by default.

### What about miner revenue?

Miners still earn rent through the continuous depletion mechanism. The total rent
collected is the same or higher. The confiscation branch was an emergent behavior,
not an intended revenue design.

## Test Vectors

### Test 1: Funded box
```
Box: 1.0 ERG, 100 TOKEN_A, created at height 1,000,000
Height: 1,100,000
Rent owed: 0.00951 ERG
Status: ACTIVE
```

### Test 2: Approaching archival
```
Box: 0.002 ERG, NFT_X, created at height 1,000,000
Height: 1,020,000
Status: APPROACHING ARCHIVAL
Note: NFT_X remains owned by the original script.
```

### Test 3: Revival
```
Box: 0.001 ERG, 500 TOKEN_B, archived
Owner submits revival with 1.0 ERG.
Result: Box revived with 0.899 ERG + 500 TOKEN_B.
```

### Test 4: Third party cannot claim
```
Third party attempts to spend a box they don't own.
Result: REJECTED. No age-based bypass exists.
```

## Backwards Compatibility

This is a hard fork. All nodes must upgrade. Existing boxes transition to new rules.
Funded boxes continue rent-bleed only. Underfunded boxes follow archival rules.
After Phase 2, new boxes must meet minimum value.
