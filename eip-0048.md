EIP-0048: Storage-Rent Repairs
==============================

* Author: arkadianet
* Status: Proposed
* Created: 19-Jul-2026
* License: CC0
* Forking: Hard Fork (fixed-height activation)

Motivation
----------

Storage rent (demurrage) exists to recirculate lost coins: any box unspent
for the storage period (4 years) may be spent by anyone, with a small fee
going to the claimer and the remainder recreated for the original owner.
Two independent defects currently exempt whole classes of boxes from this
mechanism — permanently, in the case most storage rent was designed for
(abandoned boxes whose keys are lost):

**1. The EIP-27 deadlock.** Two rules, each correct in isolation,
contradict each other when a rent-claimed box carries the re-emission
token:

* `checkExpiredBox` (`ErgoInterpreter.scala`), recreate branch
  (`box.value > storageFee`): the claimed output must preserve every
  register except R0 (value) and R3 (creation info) — **including R2
  (tokens)**.
* `verifyReemissionSpending` (`ErgoTransaction.scala`), active above the
  EIP-27 activation height: when any non-emission input carries the
  re-emission token, **no output may carry it**, and 1 nanoErg per token
  must be paid to the pay-to-reemission contract.

The recreated output the first rule requires is exactly the output the
second rule forbids. No transaction shape satisfies both:

* dropping only the token fails `checkExpiredBox` (register equality is
  all-or-nothing);
* adding a compliant pay-to-reemission output elsewhere does not help —
  the no-token-outputs check applies to every output independently;
* the full-consume branch (`box.value <= storageFee`), which imposes no
  output constraints, is unreachable: post-activation, only emission-tx
  outputs can carry the token (`verifyReemissionSpending` itself prevents
  any other box from being created with it), and a reward box's value
  (≥ 3 ERG) always far exceeds its storage fee (~0.17 ERG at current
  parameters).

Consequently every unclaimed post-777,217 miner reward box still holding
re-emission tokens becomes permanently rent-immune once it ages past the
storage period. This is not theoretical: the first such box —
`fbf119cbeb73cadc5866f63931599c85e26ea603b9db6d4a97914b88f1f82cfb`
(63 ERG, created at height 777,693) — crossed the eligibility line at
height ~1,828,900, and a live mainnet reference node rejects **both**
possible claim shapes for it via `POST /transactions/check`:

| claim shape | satisfies | node verdict |
|---|---|---|
| token-preserving recreation | `checkExpiredBox` | ✗ "Transaction should conform EIP-27 rules" |
| token dropped + 12 ERG to pay-to-reemission | `verifyReemissionSpending` | ✗ input script verification fails (`checkExpiredBox` → false) |

Measured at height ~1,831,846: 10,917 unspent sub-100K-ERG boxes carry the
re-emission token (~192K ERG; the bulk are recent rewards awaiting routine
sweeps); 17 boxes / ~1,026 ERG have been unswept for over 4 years. The
eligibility window rolls forward one block per block until ~3,067,199, so
every genuinely abandoned box in it joins the permanently-exempt set.

**2. Int-wrapping storage fee.** The fee is computed as

```scala
val storageFee = params.storageFeeFactor * box.bytes.length   // Int × Int
```

and wraps in 32-bit arithmetic (see also ergo#2251 / PR ergo#2375). At the
default factor 1,250,000:

* **len ≥ 1,718 bytes** — the product wraps negative. Then
  `storageFeeNotCovered = box.value - storageFee <= 0` is false (value
  minus a negative is large-positive), so the recreate branch demands
  `output.value ≥ box.value + |fee|` — the claimer must recreate the box
  with *more* value than it holds (up to ~2.15 ERG of subsidy).
  Effectively rent-immune.
* **len ≥ ~3,436 bytes** — the product wraps past `Int` range back to a
  small positive number; the box is claimable at a fee unrelated to its
  size.

Both regions are reachable within the 4,096-byte box size cap, and the
wrap points move whenever the voted `storageFeeFactor` changes (at the
2,500,000 cap the first wrap drops to ~859 bytes).

Both defects strand UTXOs from the mechanism built to recirculate lost
coins. Both fixes make currently-**invalid** transactions valid (a
relaxation). This cannot be deployed as a soft fork: the storage-rent
predicate (`ErgoInterpreter.checkExpiredBox`) runs unconditionally on
every node — it is not behind the script-version deferral that carried
5.0/6.0, and a failing result surfaces as the non-disableable
`txScriptValidation` rule (119), so Ergo's soft-fork machinery cannot
switch it off. An un-upgraded node therefore runs the legacy predicate,
rejects the first block carrying a new-form claim, and splits. These
repairs require a **hard fork** — a fixed activation height every node
must upgrade before (see Activation).

Specification
-------------

Let `H` = the activation height chosen for the hard fork. Below `H` the
exact legacy behavior runs; at and above `H` the repaired behavior runs.
All changes are in `ErgoInterpreter.checkExpiredBox`;
`verifyReemissionSpending` is **unchanged**. The gate is a height, not a
block/script version — the repairs are deliberately decoupled from any
concurrent script-version (v4) rollout.

### Storage fee (both branches)

```scala
val storageFee: Long =
  if (currentHeight >= H) params.storageFeeFactor.toLong * box.bytes.length
  else (params.storageFeeFactor * box.bytes.length).toLong   // legacy Int wrap
```

The 64-bit product cannot overflow within parameter bounds
(max factor 2,500,000 × max box size 4,096 ≈ 1.02 × 10¹⁰ ≪ 2⁶³). The
legacy wrapping arithmetic is preserved verbatim below `H`
because the wrap is consensus-observable: claims valid under the wrapped
fee must keep validating in historical blocks.

### Re-emission carve-out (recreate branch)

Let `reemissionDebt` = the amount of the chain's re-emission token
(`chainSettings.reemission.reemissionTokenId`) carried by the input box,
in token units — equal to the nanoErg owed to the pay-to-reemission
contract under EIP-27 (1 nanoErg per token). `reemissionDebt = 0` when
the height is below `H`, when re-emission rules are not active on the chain,
or when the box carries none.

From `H`:

1. `storageFeeNotCovered` becomes
   `box.value - storageFee - reemissionDebt <= 0` (a box that cannot cover
   fee + debt is fully consumable, as before).
2. `correctOutValue` becomes
   `output.value >= box.value - storageFee - reemissionDebt` — the
   recreation floor drops by exactly the debt being released.
3. Register preservation is unchanged for all registers **except R2
   (tokens)** when `reemissionDebt > 0`: the recreated output's token list
   must equal the input's token list **with the re-emission token entry
   removed** (relative order of remaining tokens preserved). In
   particular, the recreated output must not carry the re-emission token.

No change to `verifyReemissionSpending` is required or proposed: once the
recreated output legally drops the token, the existing rule already
requires the transaction to pay exactly `reemissionDebt` nanoErg to the
pay-to-reemission contract — which clause (2) has released from the
recreation floor. The rent path thereby *executes* the EIP-27 burn
obligation instead of deadlocking against it.

From `H`, EIP-27 enforcement (the transaction-wide `verifyReemissionSpending`
check, the activation-height injection branch, and this carve-out) is
**mandatory** and derived only from consensus state — the activation
height, the block, and a well-formed re-emission token id. It must not
depend on any node-local policy flag (`checkReemissionRules`), which below
`H` remains an optional local soft-fork check as today. Debt is summed
across matching entries with checked arithmetic, and the recreation floor
is compared before subtraction so a maximal token amount cannot underflow
and misroute a fully-consumable box into the recreate branch.

### Worked example

Box `fbf119cb…f82cfb`: 63 ERG, 12,000,000,000 re-emission tokens, 135
bytes → storage fee 0.16875 ERG.

| output | value | enforced by |
|---|---|---|
| recreated box (same script/owner/registers, token dropped) | 50.83125 ERG | `checkExpiredBox` (this EIP) |
| pay-to-reemission contract | 12 ERG | `verifyReemissionSpending` (unchanged) |
| claimer | 0.16875 ERG | ERG conservation |

The owner (possibly lost) retains everything they were not already
obligated to pay on their next spend; the claimer earns the standard rent
fee; 12 ERG flows to the re-emission contract and thence to future miner
emissions. EIP-27 accounting is exact to the nanoErg.

Activation
----------

Fixed-height hard fork. A release fixes a single consensus height `H`,
chosen far enough in the future that all nodes upgrade before it (a
Satoshi-style flag-day, not a miner-voted version bump). At `H` every
repaired rule above flips simultaneously; below `H` the legacy behavior
is reproduced verbatim.

A soft fork is not available here (see Motivation): the relaxation makes
currently-invalid claims valid, an un-upgraded node runs the legacy
`checkExpiredBox` unconditionally, and its failure surfaces as the
non-disableable `txScriptValidation` rule — so the soft-fork
rule-disable / version-passthrough machinery cannot carry it. The only
soft-fork-shaped alternative would disable EIP-27 enforcement network-wide
(rule `txReemission`, which *is* disableable), permitting the
token-preserving recreation on legacy nodes — but that removes EIP-27 burn
enforcement for all transactions, which is not an acceptable fix.
Consequently a coordinated hard fork is required.

The gate is a **height**, deliberately decoupled from any concurrent
script-version (v4) rollout, so these node-level repairs need not ride a
script/interpreter version bump. Because everything below `H` is
byte-identical to today:

* historical blocks validate unchanged;
* merging the reference implementation ahead of `H` changes nothing on
  any live network — the gated branches are unreachable until the height
  is reached.

Note that the ungated form of the arithmetic fix (PR ergo#2375) flips
transaction verdicts between patched and unpatched nodes immediately upon
upgrade — its own regression-test transaction is invalid under 6.0.x
rules and valid under the patch — and is therefore not deployable without
this height gate.

Backwards compatibility
-----------------------

* Boxes without the re-emission token and below the first wrap point:
  byte-identical behavior at all versions.
* Networks without EIP-27 (e.g. the public testnet): the carve-out is
  inert (`reemissionDebt = 0` always); only the arithmetic fix applies
  from activation.
* Both repairs are **pure relaxations** at the fee level: because
  `correctOutValue` is a floor (`>=`), not an equality, undercollection is
  always permitted, so every claim valid under the legacy wrapped fee
  (including second-wrap boxes claimed at the small wrapped fee) stays
  valid under the larger true fee. Nothing that was valid becomes invalid;
  the only new-valid claims are on the previously rent-immune boxes (the
  deadlocked re-emission boxes and the first-wrap subsidy-only boxes). No
  historical block changes validity.

Reference implementation
------------------------

https://github.com/ergoplatform/ergo/pull/2438 (draft; branch:
https://github.com/arkadianet/ergo-scala/tree/fix/storage-rent-repairs).
The reference branch currently gates on a block-version constant; it is
being reshaped to gate on the consensus height `H` once the height is
chosen, with EIP-27 enforcement made consensus-derived (independent of the
local `checkReemissionRules` flag), overflow-safe debt arithmetic, and
H-1 / H / H+1 plus reorg coverage.

* `ErgoInterpreter.checkExpiredBox` — both gated rule changes;
* `ErgoInterpreter` gains the re-emission token id as an optional
  constructor argument, threaded from `chainSettings.reemission` at the
  three node construction sites (candidate generation, block execution,
  mempool validation);
* `ExpirationSpecification` / `StorageRentRepairsSpecification` properties
  pin the new-valid claims (first-wrap uncollectable → fully consumable;
  the true fee is charged with no currently-valid claim broken;
  token-dropped claim invalid → valid; token-kept claim rejected under the
  repaired rule), the real mainnet box, local-policy independence, both
  activation boundaries, duplicate token entries and maximal debt,
  alongside the untouched legacy properties.

An independent Rust-node implementation of the *current* (pre-fork) rules'
consequence — the claim builder must skip re-emission-token boxes — with
the live-node rejection vectors captured as test fixtures:
https://github.com/arkadianet/ergo/pull/225

Related work
------------

* **EIP-27** (emission retargeting): source of the re-emission token and
  the burn rule this EIP's carve-out cooperates with.
* **EIP-0033** (Burn tokens in rent collection, scalahub): proposes
  *tightening* the full-consume branch — burning all tokens instead of
  letting the claimer seize them, protecting dApps that assume locked
  tokens stay locked. Orthogonal and composable with this EIP: EIP-0033
  concerns the full-consume branch and tokens generally; this EIP
  concerns the recreate branch, the re-emission token specifically, and
  the fee arithmetic. (Under this EIP the re-emission token is dropped —
  burned — in both branches, which is also EIP-0033-consistent.)
* **ergo#2251 / PR ergo#2375**: the fee-overflow bug report and an
  ungated arithmetic fix; this EIP supplies the activation mechanism it
  needs.
