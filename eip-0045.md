# Prepaid Storage Rent with Archival and Revival

- Author: [TheTrunk, Zelcore / Flux team]
- Status: Proposed
- Created: 22-September-2026
- Last edited: 22-September-2026

## Abstract

This proposal replaces Ergo's current storage-rent confiscation mechanism with a prepaid,
continuous-depletion model. Instead of a binary event every 4 years where underfunded boxes
are claimed in their entirety by third parties, boxes deplete their rent budget continuously
per block. When exhausted, boxes enter an archived state (pruned from the active UTXO set)
that the owner can revive at any time by paying accrued rent. Third parties can never claim
another user's assets.

## Motivation

The current storage-rent mechanism serves a legitimate purpose: funding state storage and
providing post-emission miner income. However, its enforcement branch — whole-box
confiscation when rent cannot be paid — creates a systemic risk for token custody that
no other major blockchain permits.

A 30-day audit (September 2026) documented the real-world impact:

- 42,433 boxes claimed from 5,402 addresses by two operators
- 6,300 boxes confiscated outright: ERG, tokens, NFTs, everything
- 458 distinct tokens affected, including a stablecoin (SigUSD) and wrapped assets
- Median survival once a box becomes claimable: 6 minutes
- Professional operators with 77,532 lifetime transactions

Most critically: on September 21, 2026, 415,000,000 FLUX (94.3% of a token's supply) was
taken from a project's bridge reserve. No private key was compromised. No signature was
forged. The transaction contained no proof bytes because none are required under the
confiscation branch.

The problem is not the concept of storage rent. The problem is that the enforcement
mechanism — confiscation of unrelated assets — is disproportionate to the cost it
recovers. A parking meter charges for the time occupied; it does not seize the vehicle.

### Design Goals

1. **Preserve rent as a storage cost mechanism** (miners still earn rent income)
2. **Preserve state cleanup** (neglected boxes eventually leave the active UTXO set)
3. **Eliminate asset confiscation** (no third party can ever claim another's box)
4. **Maintain backward compatibility** where feasible
5. **Be implementable with moderate engineering effort**

### Comparison to Other Chains

| Chain | Approach | Can third parties take tokens? |
|---|---|---|
| Solana | Rent-exempt minimums (mandatory) | No |
| Cardano | Min-ADA per UTxO (at creation) | No |
| Nervos | State priced in the native asset | No |
| Ethereum | Gas on writes; statelessness roadmap | No |
| **Ergo (current)** | Storage rent + confiscation | **Yes** |

## Specification

### Overview

The proposal introduces three coordinated changes:

1. **Continuous rent depletion** — rent is deducted per block, not per 4-year period
2. **Archival instead of confiscation** — exhausted boxes are archived, not claimed
3. **Revival mechanism** — owners can revive archived boxes at any time

### Continuous Rent Depletion

Replace the current periodic rent model with per-block depletion.

**Current model:**
```
every 1,051,200 blocks:
    if box.value >= RENT_FEE + MIN_BOX_VALUE:
        box.value -= RENT_FEE  (returned to owner's script)
    else:
        entire box claimed by collector  (the confiscation branch)
```

**Proposed model:**
```
every block:
    box.rent_remaining -= RENT_PER_BLOCK
    // where RENT_PER_BLOCK ≈ 0.0000000951 ERG
    // (= ~0.1 ERG per 1,051,200 blocks / current rate)
    
    // No action is taken on the box itself.
    // The depletion is computed implicitly from (currentHeight - creationHeight).
    // No transaction is needed. No third party is involved.
```

The rent for any box at any point in time is:
```
rent_owed(height) = (height - box.creationHeight) × RENT_PER_BLOCK
rent_remaining(height) = max(0, box.value - rent_owed(height) - MIN_BOX_VALUE)
```

This means:
- A box with 1 ERG covers ~40 years at current rates
- A box with 0.001 ERG covers ~12 days
- The "rent status" of any box is deterministically computable from its creation height
  and value — no separate tracking needed

**Key property**: rent depletion is passive. No transaction is required. No collector
is needed. The box simply accrues rent debt that is implicitly deducted from its value.

### Archival State

When a box's ERG value is fully consumed by rent, it transitions to an **archived** state.

**Definition**: A box is archived when `box.value - rent_owed(currentHeight) < MIN_BOX_VALUE`.

**Behavior of archived boxes:**
- Removed from the active UTXO set (achieves state cleanup)
- The box still exists in the blockchain's immutable history
- The box's tokens are NOT transferred to anyone
- The box's script remains unchanged
- No one can "claim" or "collect" an archived box

**What archived does NOT mean:**
- It does NOT mean the box is destroyed
- It does NOT mean the tokens are burned
- It does NOT mean ownership transfers
- It does NOT mean the box is lost forever

Archived is a state where the box is temporarily outside the active UTXO set but
can be brought back by its owner. This is analogous to a file being moved from
active storage to cold storage — the file still exists, it's just not immediately
accessible without a retrieval step.

### Revival Mechanism

An owner can revive an archived box by submitting a **revival transaction**.

A revival transaction:
1. References the archived box (by `boxId` and the block containing it)
2. Includes a proof that the box existed at that block (Merkle proof)
3. Provides new ERG to fund the box going forward
4. Is signed by the owner (the archived box's script must evaluate to true)

```scala
// Revival transaction structure
revival_tx = {
    inputs: [
        {
            boxId: archived_box.boxId,
            // Proof: signed by the owner's key (evaluates the archived box's script)
            spendingProof: <owner_signature>,
            // Extension: proof of the archived box's existence
            extension: {
                // Merkle proof that the box was created in block N
                // at transaction index I, output index J
                "proof": <merkle_proof>,
                "block_height": N,
                "tx_index": I,
                "output_index": J
            }
        },
        // Funding input: fresh ERG to pay for revived box + overdue rent + fee
        funding_box
    ],
    outputs: [
        {
            // The revived box: same script, same tokens, new ERG, new creation height
            ergoTree: archived_box.ergoTree,
            value: new_erg_amount - overdue_rent - tx_fee,
            tokens: archived_box.tokens,  // all tokens preserved
            creationHeight: current_height  // rent clock restarts
        }
    ]
}
```

**Overdue rent calculation:**
```
overdue_rent = min(
    (current_height - last_funded_height) × RENT_PER_BLOCK,
    max_rent_cap  // prevents pathological accumulation
)
```

The `max_rent_cap` limits how much back-rent can be charged, making revival
predictable and affordable regardless of how long the box was archived.

### Minimum Box Value

Every output box must have a value that covers a minimum lifetime of rent.

```
RENT_EXEMPT_MINIMUM = RENT_PER_BLOCK × BLOCKS_PER_40_YEARS
                    ≈ 1.0 ERG
```

This is a transaction validation rule: outputs below this threshold are rejected.
Existing boxes below the threshold are grandfathered (they follow the archival
rules above, not the new-creation rules).

## Implementation Notes

### Node changes

1. **UTXO set pruning**: Nodes periodically remove archived boxes from their active
   UTXO set. The threshold for pruning can be configurable (e.g., "boxes that have
   been archived for > 1 year").

2. **Revival validation**: Nodes validate revival transactions by:
   - Checking the Merkle proof against the referenced block
   - Verifying the archived box's script (the owner's signature)
   - Checking that the box hasn't already been revived (double-spend prevention)
   - Collecting the overdue rent + fee

3. **Rent calculation**: The rent owed on any box is computed on-the-fly from
   `(currentHeight - creationHeight) × RENT_PER_BLOCK`. No storage needed.

### Wallet changes

1. **Box building**: Wallets must attach ≥ `RENT_EXEMPT_MINIMUM` ERG to every output.
   Most wallets already do this (or something close).

2. **Archived box tracking**: Wallets should inform users when boxes are approaching
   archival. A simple "X ERG remaining, Y days of rent coverage" indicator.

3. **Revival UI**: A "Revive archived boxes" feature that constructs revival
   transactions for the user.

### Migration path

1. **Phase 1 (activation height H1)**: The confiscation branch is disabled.
   All existing boxes follow the rent-bleed-only model (rent deducted, tokens
   preserved). No new confiscations can occur.

2. **Phase 2 (activation height H2, H1 + ~6 months)**: Minimum box value enforcement
   begins for new transactions. Wallets have had 6 months to update.

3. **Phase 3 (ongoing)**: Archival and revival mechanisms activate. Boxes that
   exhaust their rent budget enter archival state.

## Rationale

### Why prepaid per-block depletion rather than periodic?

The current 4-year periodic model creates a cliff: a binary moment when a box either
pays or is confiscated. This cliff is:
- Hard to communicate to users ("set a reminder for 4 years from now")
- Exploitable by bots (median response: 6 minutes past the cliff)
- Anxiety-inducing ("am I about to lose my assets?")

A continuous model has no cliff. Rent is a slow, predictable, invisible cost —
like electricity in a rental unit. Users don't think about it until they get a
low-balance warning, at which point they top up.

### Why archival rather than permanent deletion?

State cleanup is the legitimate motivation for storage rent. However, "cleanup"
should not mean "someone else takes your stuff." Archival achieves the state-
cleanup goal (active UTXO set shrinks) while preserving the owner's property
rights (they can revive).

This is the same principle as:
- A storage unit operator who moves unpaid items to a locked facility (not to their own home)
- A bank that freezes a dormant account (rather than giving the balance to the teller)
- A library that moves un-borrowed books to archive stacks (rather than burning them)

### Why a rent-exempt minimum?

Without a minimum, wallets can still create boxes that will be archived quickly.
This creates:
- User confusion ("my tokens disappeared")
- Support burden for wallet developers
- Bad UX for the chain

With a minimum, every new box has decades of rent coverage by default. The problem
of "doomed boxes" is eliminated at creation time.

### What about miner revenue?

Miners still earn rent income — it's now collected through the continuous depletion
mechanism rather than through confiscation transactions. The total rent collected
is the same or higher (continuous model captures rent from all boxes, not just
those that happen to be swept).

The removal of the confiscation branch removes a revenue stream for professional
collectors (who currently keep the entire contents of swept boxes), but this was
never the intended purpose of storage rent — it was an unintended consequence.

## Test Vectors

### Test 1: Funded box, normal operation
```
Box: 1.0 ERG, 100 TOKEN_A, created at height 1,000,000
Current height: 1,100,000 (100,000 blocks later)
Rent owed: 100,000 × 0.0000000951 = 0.00951 ERG
Rent remaining: 1.0 - 0.00951 = 0.99049 ERG
Status: ACTIVE (rent remaining > MIN_BOX_VALUE)
```

### Test 2: Box approaching archival
```
Box: 0.002 ERG, NFT_X, created at height 1,000,000
Current height: 1,020,000 (20,000 blocks later)
Rent owed: 20,000 × 0.0000000951 = 0.0019 ERG
Rent remaining: 0.002 - 0.0019 = 0.0001 ERG
Status: APPROACHING ARCHIVAL (< MIN_BOX_VALUE)
Note: NFT_X is still owned by the original script. No one can take it.
```

### Test 3: Archived box revival
```
Box: 0.001 ERG, 500 TOKEN_B, created at height 1,000,000
Current height: 1,500,000 (500,000 blocks later)
Rent owed: capped at max_rent_cap (e.g., 0.1 ERG)
Status: ARCHIVED (removed from active UTXO set)

Owner submits revival transaction:
- Merkle proof of box existence at height 1,000,000
- Signed by the box's script owner
- Provides 1.0 ERG (new funding)
- Pays 0.1 ERG overdue rent + 0.001 ERG fee

Result: Box revived with 0.899 ERG + 500 TOKEN_B, new creation height 1,500,000
The 500 TOKEN_B were never at risk. They were simply in cold storage.
```

### Test 4: Third party cannot claim
```
Any address attempts to spend a box they don't own.
Result: REJECTED — the box's script must evaluate to true.
There is no age-based bypass. There is no confiscation branch.
The script is always evaluated. The key is always required.
```

## Backwards Compatibility

This is a hard fork. All nodes must upgrade.

Existing boxes are NOT invalidated. They transition to the new rules:
- Funded boxes (> 0.15 ERG): continue as before (rent-bleed only)
- Underfunded boxes (< 0.15 ERG): follow archival rules (NOT confiscated)
- At Phase 2 activation: new boxes must meet the minimum value requirement
